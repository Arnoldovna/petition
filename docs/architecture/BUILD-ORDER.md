# petition: Build order

Implements PLAN.md Etappe 2: **Scaffold (incl. CI/CD) -> Backend modules (parallel) -> Frontend modules (parallel) ->
CSS & Design (+ design review) -> Tests/E2E**. Every phase ends with the `quality-gate` skill (`pnpm verify`,
`/code-review high`, `/simplify`, `pnpm verify`, conventional commit on a feature branch, PR, `gh pr checks --watch`,
squash merge), one branch and one PR per phase or sub-phase (`project-scaffold/references/conventions.md` §3).
Prerequisite (Etappe 1): this architecture has been reviewed by the architecture critic and revised
(OVERVIEW.md section 23).

`project-scaffold/references/conventions.md` is binding for everything the three projects share (repo bootstrap,
branches, parallel model, script names, e2e and integration-test isolation, cookie names, digest pins,
CI/audit/release workflows). This file only adds petition specifics. Where conventions §1 (fnm) and §9 (no CI cost
rule) are stale, PLAN.md, ADR 0018 and ADR 0019 win (flagged for Marina).

Paths: the repository is `~/petition`, the plan is `~/PLAN.md`, the environment
script is `~/.devenv.sh`. There is no `~/Code` on this machine. The legacy code stays on the old Mac
(`~/Code/_legacy` there) and is never copied.

## Rules for every agent

- **Every shell command starts with `source ~/.devenv.sh && `** (Phase 0). The working directory
  is reset between calls, so use absolute paths.
- OVERVIEW.md, DATA-MODEL.md, ROUTES.md and the ADRs are binding. A needed change is made in the docs first and
  flagged, never silently in code.
- English in the repository. Nothing from the legacy code is copied (code, SQL, copy text, assets, values); no secret
  from the old Mac ever enters the repository.
- Fix causes. Never weaken, skip or delete a test, never add an `eslint-disable` without a same-line reason, never
  `@ts-ignore` (`quality-gate` skill).

## Rules for parallel work

1. A unit in a parallel phase creates or edits **only the files listed for it**. Everything else is read-only.
2. **Frozen files** (ADR 0019 §2): every file created in phase 1 is frozen unless a later unit's list below names it
   explicitly (stubs created to be replaced, partial markup under rule 5, global stylesheets in 4a, icons). Always
   frozen for units: the layout `src/views/layouts/main.hbs`, `src/styles/{main.css, tokens.css}`, config,
   composition root, schema, migrations, the test harness (`test/**`), the e2e helpers (`e2e/{a11y.ts, fixtures.ts}`),
   CI, `package.json` and the lockfile. A unit that needs a change to a frozen or foreign file, a new dependency or a
   migration stops and reports it; the orchestrator applies it in the phase's sequential step (2b, 3b, 4e, 5e). A
   sequential step edits only the files listed for it plus the files named in the queued requests.
3. Every BEM class used in markup must already be defined in CSS for `check:utilities` to pass. Phase 1 creates all
   21 component CSS files with stubs; each later unit adds selectors only to the CSS files it owns in that phase.
4. Feature tests live inside the feature (`features/<x>/__tests__/`), including feature-specific fakes, so test files
   never collide. Signed-in agents come from `signIn(agent, userId)` (`test/auth.ts`), never from another module's
   routes (ADR 0017).
5. **Partial parameter contracts (OVERVIEW.md section 15.2) are phase-1 API.** A unit that owns a partial may change
   its markup and CSS, never its parameter names or meaning; that is a frozen-file request (rule 2).
6. **The shared tree stays importable** (ADR 0019 §2). `createTestApp()` builds the real app, which imports every
   module's `index.ts`, and every page renders shared partials. So a unit writes its internal files first and replaces
   its stub `index.ts` **last**, after its internal files are complete and its unit tests pass; the new `index.ts`
   keeps the frozen deps interface and never throws at import or at `create<Name>Module()` time. Every saved file must
   parse (TypeScript, Handlebars, CSS); write whole files. A failure caused by a sibling's file is reported, never
   fixed.
7. **One working tree, scoped checks only** (conventions §4, ADR 0017). All units of a phase work on the phase branch
   in the same tree and do not commit. A unit runs only
   `pnpm exec vitest run --project unit --project integration <own paths>`, `pnpm exec eslint <own paths>`,
   `pnpm typecheck` (fixing only its own errors) and, for CSS, `pnpm exec stylelint "<own files>"` plus
   `node scripts/check-no-utilities.mjs .` (fixing only findings in its own files). It never runs `pnpm verify`,
   `pnpm test:e2e`, `pnpm e2e:*`, `pnpm demo`, `pnpm dev`, `pnpm dev:setup`, `pnpm infra:*`, `pnpm stack:*` or any
   docker compose command (Testcontainers is fine: random ports, one database per test file).
8. **One gate per phase.** After all units of a phase are done, the orchestrator runs the sequential step, the full
   `pnpm verify` and the quality gate (one PR, squash-merge). The next phase branches from the updated `main`, so
   every PR is verified on top of the current `main` (no rulesets on the private free-plan repo, ADR 0017).
9. **Test titles start with the requirement ids they cover** (`F-24, B-09: ...`, conventions §11, ADR 0019 §10).

## Phase 0: Machine prerequisites (done: `~/.devenv.sh`)

Phase 0 is **already satisfied** by `~/.devenv.sh` (PLAN.md Etappe 0, ADR 0019 §1). The script
changes nothing on the system, only the current shell:

- `PATH` starts with the newest installed nvm Node 26 (`~/.nvm/versions/node/v26.*`, 26.13.1 on 2026-11-16), then
  `/opt/homebrew/bin` (git 2.52, gh, docker, gitleaks 8.30.1, lefthook). `pnpm` is a corepack shim that is already on
  the user's `PATH`; corepack runs exactly `package.json#packageManager` (`pnpm@10.34.9`), and
  `COREPACK_ENABLE_DOWNLOAD_PROMPT=0` keeps it non-interactive.
- Docker Desktop is running (Compose 5.5, enough for `!reset` and `!override`, which need 2.24.4 or later), and `gh`
  is logged in as Arnoldovna with the git credential helper for `https://github.com`.
- Repository bootstrap (conventions §2) is done: `~/petition` has the docs-only first commit on
  `main`, `origin` is `Arnoldovna/petition` (private). Do not run `git init` or `gh repo create` again; never change
  the visibility.

Rules:

- Do **not** install fnm, Homebrew packages or a global pnpm (`npm i -g`), and do not edit `~/.zshrc` or other rc
  files. Conventions §1 still describes fnm and `/usr/local/bin/git`; PLAN.md wins (flagged for Marina).
- Check once per session: `source ~/.devenv.sh && node -v && pnpm -v && git --version &&
docker compose version` prints `v26.x`, `10.34.9`, git 2.31 or later and Compose 2.24.4 or later. If not, stop and
  report; never repair the machine.
- `.npmrc` `engine-strict=true` (phase 1a) turns a shell without the script into an install error.
- Playwright browsers are not part of Phase 0; 1a installs them (they need the lockfile's Playwright version).
